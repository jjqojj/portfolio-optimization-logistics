# Bogota Express VRPTW - Prescriptive Optimization Engine

An end-to-end prescriptive analytics and operations research (OR) pipeline designed to solve the **Vehicle Routing Problem with Time Windows (VRPTW)**. The engine ingests localized logistical dimensions, simulates asymmetric spatiotemporal congestion across Bogota's micro-zones, and computes optimal dispatch routes minimizing global transport time under strict industrial constraints.

---

## 🔢 Mathematical Core (MILP Formulation)

The optimization engine maps relational entities into an algebraic workspace, resolving a Mixed-Integer Linear Programming (MILP) model defined as follows:

### Sets and Indices
* V: Total operational nodes (where 0 represents the Fontibón Master Depot/CEDI, and \(C = \{1, \dots, 60\}\) represents retail stores).
* K: Homogeneous fleet of transport vehicles.

### Objective Function
Minimizes total global transit time across the operational network:
\[\min \sum_{k \in K} \sum_{i \in V} \sum_{j \in V, j \neq i} t_{ij} \cdot x_{ijk}\]

### Operational Constraints
1. **Single-Service Visit Guarantee:** Each retail customer must be visited exactly once by exactly one vehicle:
\[\sum_{k \in K} \sum_{j \in V, j \neq i} x_{ijk} = 1 \quad \forall i \in C\]

2. **Conservation of Flow (Nodal Equilibrium):** A vehicle entering a store node must depart from it:
\[\sum_{i \in V, i \neq m} x_{imk} = \sum_{j \in V, j \neq m} x_{mjk} \quad \forall m \in C, \forall k \in K\]

3. **Depot Continuity:** Vehicles depart and return to the master depot at most once:
\[\sum_{j \in C} x_{0jk} \le 1, \quad \sum_{i \in C} x_{i0k} \le 1 \quad \forall k \in K\]

4. **Vehicle Payload Capacity:** Total allocated demand \(q_i\) cannot exceed max vehicle weight allowance \(Q_k\):
\[\sum_{i \in C} q_i \left( \sum_{j \in V, j \neq i} x_{ijk} \right) \le Q_k \quad \forall k \in K\]

5. **Temporal Continuity & Subtour Elimination (Big-M Technique):** Enforces strict chronological arrival bounds \(w_{ik}\), considering service times \(s_i\) and travel friction \(t_{ij}\):
\[w_{ik} + s_i + t_{ij} - w_{jk} \le M(1 - x_{ijk}) \quad \forall i,j \in V, i \neq j, \forall k \in K\]
\[e_i \le w_{ik} \le l_i \quad \forall i \in V, \forall k \in K\]

## 🏗️ System Architecture & Data Flow

The project bypasses monolithic script dependencies by utilizing a strict decoupled layer design:

```text
[Raw CSV Data] ──> [database_manager.py] ──> [DuckDB Warehouse]
                                                   │
   ┌───────────────────────────────────────────────┘
   ▼
[distance_matrix.py] ──> Computes Vectorized Haversine Meshgrids (NumPy)
   │
   ▼
[traffic_engine.py]  ──> Simulates Dynamic Traffic Friction Matrix
   │
   ▼
[vrptw_data_model.py] ──> Hydrates Database Records into Mathematical Sets
   │
   ▼
[vrptw_data_solver.py] ──> Executes Branch-and-Bound Linear Solver (PuLP)
```

* **Data Engineering Layer:** `LogisticsDatabaseManager` initializes a structured star-schema warehouse within DuckDB. Input entities are generated by `BogotaDataGenerator` and written to disk via `BogotaDataIngestion`.
* **Spatial Analytics Layer:** `HaversineDistanceMatrixCalculator` computes an asymmetric matrix leveraging vectorized floating-point operations through NumPy meshgrids.
* **Temporal Simulation Layer:** `TrafficSimulationEngine` acts as a kinematic conversion layer, applying dynamic penalties across specific temporal windows (`off_peak`, `mid_day`, `rush_hour`) and high-density bottlenecks (e.g., Chapinero, Usaquén).
* **Prescriptive Engine Layer:** `MIPRouteSolver` parses the data container via `VRPTWDataModel`, maps variables into PuLP, and invokes the CBC solver engine.

## 🚀 Installation & Execution

### Prerequisites
* Python 3.10 or higher installed.
* Git Bash or equivalent terminal.

### 1. Clone the Repository & Setup Environment
```bash
git clone https://github.com/your-username/portfolio-optimization-logistics.git
cd portfolio-optimization-logistics/src

# Create and activate virtual environment
python -m venv venv
source venv/Scripts/activate  # On Windows Git Bash
```

### 2. Install Dependencies
```bash
pip install -r requirements.txt
```

### 3. Run the Automated Orchestration Pipeline
Execute the master director script to trigger all operational stages (`Ingestion` ──> `Spatial Analysis` ──> `Traffic Simulation` ──> `Prescriptive Optimization`) sequentially with a single command:
```bash
python main.py
```
